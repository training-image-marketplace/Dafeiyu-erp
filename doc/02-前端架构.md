# 02 前端架构

> 代码：`erp-system/web/`。后端接口见 [doc/05](05-API设计.md)。

## 1. 技术栈

| 项 | 选择 |
| --- | --- |
| 框架 | Svelte 5（runes：`$state` / `$derived` / `$props`） |
| 构建 | Vite |
| 样式 | Tailwind + bits-ui（shadcn-svelte 风格的自建 ui 组件） |
| 图标 | lucide（`lib/icons.ts` 集中登记） |
| e2e | Playwright |

构建产物 `dist/` 由**后端**托管（`APP_WEB_DIR`），所以生产只需要一个进程、一个镜像。

## 2. 目录

```
src/
├── lib/
│   ├── api/          # client.ts（fetch + CSRF + 401 处理）、types.ts、delete.ts
│   ├── components/   # app-shell、列表通用件、ui/*、erp/*（业务弹窗）
│   ├── i18n/         # zh-CN / en-US，缺键由后端 Go 测试兜底
│   ├── stores/       # session / confirm / notify / tabs
│   ├── list-state.svelte.ts   # 分页 + 筛选 + URL 同步
│   └── router.svelte.ts       # 基于 import.meta.glob 的路由
└── pages/            # 每个 .svelte 自动成为一个路由
```

## 3. 路由：页面就是路由

`router.svelte.ts` 用 `import.meta.glob('../pages/**/*.svelte', { eager: true })`
把页面收成模块表，键是 `../pages/erp/goods.svelte` 这种路径：

- 菜单里的 `component`（如 `erp/goods`）与文件路径一一对应；
- 找不到组件时返回 null 并提示，不让整个应用崩掉（菜单是库里的数据，可能指向已删页面）；
- **内置路由**（`builtinRoutes`）不来自菜单：`/dashboard`、`/profile`，
  任何登录用户都能进，避免「没配菜单 = 什么都做不了」；
- 导航用 `navigate` / `replaceTo`；列表改筛选/翻页用 `replaceQuery`（只写不读，
  不污染浏览器历史）。

## 4. 会话与权限

`stores/session.svelte.ts` 只暴露 getter：

| 成员 | 用途 |
| --- | --- |
| `session.user` | 当前用户 |
| `session.can(code)` | 权限判断，`isAdmin` 兜底 |
| `session.hasRole(code)` | 身份判断（按角色而不是权限码） |
| `session.menus` | 后端返回的菜单树，前端只渲染它 |

- 页面用 `{#if session.can('erp:master:edit')}` 隐藏按钮，**服务端仍会再校验**；
- 刷新页面后 cookie 还在、CSRF 只在内存，所以启动必须重新 `GET /auth/me`；
- 任何 401 由 `api/client.ts` 统一清会话回登录页。

## 5. 列表页统一状态机

`createListState({ endpoint, filterKeys, exportPath })` 收掉六个列表页原本各自手写的
一整套逻辑：分页、筛选、加载、导出链接、URL 同步、越界回退。

页面只写：列、筛选控件、弹窗。约定：

- 筛选值一律是字符串，类型转换由页面自己做；
- 服务端会把越界 `page` 钳到最后一页，以前端收到的 `res.page` 为准；
- 删掉本页最后一条时自动回退一页（`refreshAfterDelete`）；
- 导出链接直接给 `<a href>`，筛选条件跟着带上——导出的是屏幕上那些行。

## 6. 双语

- 文案一律 `t('key')`，词条在 `i18n/zh-CN.ts` 与 `i18n/en-US.ts`（各 600+ 条）；
- `en-US` 的类型是 `Record<keyof typeof zhCN, string>`，漏一条编译期就报错；
- 后端只返回 `msg` 键（如 `error.notFound`），由 `i18n/errors.ts` 翻译；
  Go 侧测试会扫描后端用到的 `error.*` 键，前端缺词条时测试失败。

## 7. 页面清单（29 个）

| 分组 | 页面 |
| --- | --- |
| 基础数据 | `erp/goods`、`erp/customers`、`erp/suppliers`、`erp/warehouses`、`erp/classifications`（分类/品牌/单位） |
| ERP 数据 | `erp/stock`、`erp/purchase`、`erp/sales`、`erp/purchase-return`、`erp/sales-return`、`erp/transfers`、`erp/stock-checks`、`erp/reports` |
| 审核中心 | `erp/audit-in`、`erp/audit-out` |
| 工作台 | `erp/dashboard` |
| 系统 | `system/users`、`system/roles`、`system/menus`、`system/apis` |
| 监控 | `monitor/system`、`monitor/sessions`、`monitor/loginlogs`、`monitor/operlogs` |
| 工具 | `tool/files`、`tool/jobs` |
| 运维 | `erp/switches`（缺陷开关）、`erp/android`（客户端下载） |
| 其它 | `profile` |

菜单树在 `sys_menus`（迁移种子 `0015` / `0018` / `0020` / `0021`），
`ERP 业务` 下分「基础数据 / ERP 数据 / 审核中心」三组目录，另挂两个独立页面「缺陷开关」「Android 客户端」；目录只负责分组、不带 `component`。

## 8. 业务组件

`lib/components/erp/` 放跨页面复用的业务件（单据明细行、审核弹窗、状态徽标等）；
通用件在 `lib/components/`（`filter-bar`、`pagination`、`list-header`、`toast` 等）；
基础 UI 在 `lib/components/ui/`（button / input / dialog / table / badge / card …）。

**约定**：`pages/` 下不能放复用组件——那里每个 `.svelte` 都会被当成路由。

## 9. 开发与构建

```bash
npm ci
npm run dev            # :5173，/api 与 /healthz 代理到 :8889（见 vite.config.ts）
npm run check          # svelte-check + tsc，提交前必须 0 error
npm run build          # 产出 dist/，由后端托管
npx playwright test    # e2e（需先起后端）
```

> 只起前端是打不开的：`/api` 只是代理，后端没起会 502。
