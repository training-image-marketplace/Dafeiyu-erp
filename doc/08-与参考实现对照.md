# 08 与参考实现对照

> 对照对象：`ContainerManagement/erp-system`（已交付外包项目，Gin-Vue-Admin + Vue 3）。
> 本仓库是按需求重写的实现，**没有复制其代码、文档或界面**。本文件只记差异与取舍。

## 1. 结论

1. **骨架齐平、单据闭环已补齐**：认证、RBAC、菜单、权限码、审计、定时任务、文件、
   CSV 导入导出都在，约束更严（服务端二次校验、启动校验、CSRF、限流、`GET_LOCK` 迁移）。
2. **主数据字段已补齐**：单位独立成表，客户/供应商带地址与结账方式，
   商品带规格与建议采购/销售价，仓库带专员/电话/地址。
3. **仍缺站内信**：参考实现审核后会通知制单人，本仓库没有消息表，
   「提交 → 审核 → 收到通知」还差最后一步。
4. **缺陷目录偏小**：参考 67 条，本仓库声明 6 条、实际生效 4 条
   （`BUG-004` / `BUG-006` 未接线）。教学价值主要在「同一功能多种缺陷」，
   建议按模块补到 20~30 条。
5. **不建议 1:1 照搬**：参考的软删除、整型状态码、按 `authorityId` 硬编码的数据权限、
   「审核即入账」都与本项目「显式状态 + 代码声明权限 + 可分步测试」的设计冲突。

## 3. 单据状态机

参考实现：`0 草稿 / 1 已提交 / 2 已审核 / 3 已驳回`，**审核即入账**（同一个事务里改状态 + 动库存）。

本仓库：

```
draft ──submit──▶ submitted ──approve──▶ approved ──receive/ship/complete──▶ completed
  ▲                 │  │
  └──withdraw───────┘  └──reject──▶ rejected
```

- 审批与入账**分两步**：`approve` 只改状态，`receive` / `ship` / `complete` 才写库存。
  这样「审批」和「入账」各自可测，缺陷更容易定位到具体环节。
- 若要与参考对齐成「审核即入账」，要同时改状态机、前端按钮与验收用例，代价大于收益。

## 4. 刻意保留的差异

| 主题 | 参考 | 本仓库 | 原因 |
| --- | --- | --- | --- |
| 认证 | JWT + 黑名单 | Cookie + 服务端 session + CSRF | 可强退、可审计、无令牌泄露面 |
| 授权 | casbin + `sys_apis` | 代码声明权限码 + 启动校验 | 漏写权限码启动即失败 |
| 状态 | 整数 + 软删除 | 字符串 + CHECK，不软删除 | 语义可读、约束交给数据库 |
| 库存 | 只查余额 | 余额 + 流水 + 调整 | 可追溯，也是测试点 |
| 缺陷开关 | 全局 | 按作用域，平台物化到实例 | 一节课、一个组、一个学生可以不同 |
| UI | Element Plus | Svelte 5 + shadcn-svelte 风格 | 不复用外包 UI，按需求重写 |
