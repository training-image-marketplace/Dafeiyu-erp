# 01 后端架构

> 代码：`erp-system/server/`。读这一份之前先看 [README](../README.md)。

## 1. 技术栈与分层

| 项 | 选择 |
| --- | --- |
| 语言 | Go 1.25 |
| HTTP | Gin |
| 数据访问 | `database/sql` + 手写 SQL，不用 ORM |
| 数据库 | MySQL 8.0.16+（InnoDB / utf8mb4 / UTC） |
| 认证 | Cookie + 服务端 session + CSRF 双提交 |
| 日志 | `log/slog`（logfmt），带 request_id |

```
cmd/server/            进程入口、手工 DI
internal/handler/      HTTP 参数解析与响应，不含业务规则
internal/service/      业务规则、事务边界、跨仓储编排
internal/repository/   SQL、迁移、连接池
internal/domain/       实体与领域错误（不依赖外部包）
internal/perm/         权限码声明 + 页面/按钮授权树
internal/middleware/   认证、CSRF、限流、操作日志、安全头
internal/httpserver/   路由注册、静态资源、优雅退出
```

**三条铁律**（改代码时别破）：

1. handler 不碰 `*sql.DB`，service 不拼 SQL。
2. 错误用 `domain.ErrXxx` 包装，统一由 `httpx.FailFromError` 映射成状态码 + i18n 键；
   handler 里不写中文文案（前端按 `msg` 键翻译）。
3. 新增路由必须在 `reg.protect(...)` 里带一个已声明的权限码，否则启动即失败
   （`perm.Declared` 校验，测试 `TestEveryProtectedEndpointHasADeclaredPerm` 也会拦）。

## 2. 启动装配

`cmd/server/main.go` 按顺序做这几件事，任何一步失败都直接退出：

1. 读配置（`config/config.yaml` + 环境变量，后者优先）；
2. 建连接池（`loc=UTC`，会话 `time_zone='+00:00'`）；
3. `repository.Migrate`：`GET_LOCK` 串行执行迁移，失败保留 `dirty` 标记；
4. 校验库里出现的权限码都在 `perm` 声明过（出现未知码拒绝启动）；
5. 手工装配 repository → service → handler；
6. `httpserver.NewRouter` 注册路由，同时返回路由表（启动日志会打印端点数量）；
7. 启动定时任务，监听 SIGINT/SIGTERM 优雅退出。

## 3. 一条请求经过什么

```
Recovery → RequestID → RequestLogger → SecureHeaders → BodyLimit → RateLimit
   → Require（会话）→ CSRF → OperationLog → MenuSwitchGate → RequirePerm → handler
```

顺序是有意的：

- `OperationLog` 排在权限校验**之前**，403 越权试探也会被记下来；
- `MenuSwitchGate` 在权限之前，菜单关闭时返回 403，与权限无关；
- `BodyLimit` 把 `/api/v1/files` 排除在外，上传走自己的上限。

### 3.1 菜单开关网关

`internal/handler/erp_handler.go` 的 `menuCodeOfPath` 按**资源段精确匹配**
（`/api/v1/sales-returns/3` → `sales_return`），不做前缀匹配——`sales` 与 `sales-returns`
前缀重叠，前缀匹配 + map 迭代顺序会让判定随机失效（历史 bug，已由
`menu_gate_test.go` 钉住）。作用域固定 `all`：容器里只认这一层。

### 3.2 权限

- 权限码是常量（`internal/perm/perm.go`），分 `system:*` / `erp:*` / `monitor:*` / `tool:*` 四组。
- 授权树到按钮级：`sys_menus.buttons_json` 里的按钮码与接口用的是**同一个码**，
  不存在「界面能勾、接口不认」的第二套码。
- 审批类动作（采购/销售/退货/调整/调拨/盘点的通过、驳回）统一要 `erp:audit:approve`，
  且只出现在审核中心页面。

## 4. 业务规则

### 4.1 单据状态机

```
draft ──submit──▶ submitted ──approve──▶ approved ──receive/ship/complete──▶ completed
  ▲                 │  │
  └──withdraw───────┘  └──reject──▶ rejected
```

- **审批与入账分两步**：`approve` 只改状态，`receive` / `ship` / 退货的 `complete`
  才写库存。这样「审批」和「入账」各自可测，比「审核即入账」更容易定位问题。
- 只有 `draft` 可改、可删；`submitted` 可撤销回 `draft`。
- 驳回必须写原因，落在 `erp_bill_operations.comment`。
- 每次状态变化都写一条操作记录（`erp_bill_operations`），单据详情页可查。

### 4.2 库存

- 余额 `erp_stocks`（仓库 × 商品），流水 `erp_stock_logs`（7 种 `biz_type`：
  `purchase_in` / `sales_out` / `purchase_return` / `sales_return` / `adjust` /
  `transfer-in` / `transfer-out`）。
- 动库存的路径全部在事务里 `SELECT ... FOR UPDATE` 锁行，再写余额与流水，避免并发丢更新。
- 库存不足默认拒绝（409）；`BUG-002` 打开时允许为负。

### 4.3 退货

- 退货必须挂在**已完成**的来源单上；单价取来源单明细，请求只传 `goods_id` 与 `qty`。
- 可退数量 = 来源单数量 − 其它 `submitted/approved/completed` 退货数量；
  建单时预校验，提交时在事务内用来源单行锁**再校验一次**，防止两张草稿先后提交造成超退。
- 采购退货完成时扣库存，销售退货完成时加库存。

### 4.4 库存调整 / 调拨 / 盘点

| 类型 | 规则 |
| --- | --- |
| 调整 | `direction` 明确 in/out，`qty` 必须为正；审核通过才写库存与流水 |
| 调拨 | `draft → submitted → approved → completed`；`complete` 时调出仓扣、调入仓加，写两条流水 |
| 盘点 | 账面数由服务端按当前库存读取，前端只填实盘数；审核通过按差异生成一张**已审核**的调整单入账 |

制单人默认不能自审（`BUG-003` 打开时例外）。

### 4.5 单号

`erp_bill_no_seq (prefix, next_val)` 按前缀取号，行锁保证唯一；格式见各单据
`order_no` / `return_no` / `adjustment_no` / `transfer_no` / `check_no`。

## 5. 开关与缺陷注入

- 配置表 `erp_switch_configs`（`scope` / `scope_id` / `config_json`），
  `config_json = {"bugs":{...},"menus":{...}}`，值都是布尔。
- 读取：`SwitchService.Config` 以 `all` 打底，再叠加请求声明的作用域；
  当前一律按 `all` 解析（平台在开环境/保存配置时把合并结果物化成实例的 `all`）。
- 缺陷：业务代码里是 `if s.switches.BugEnabled(ctx, domain.BugXXX, ...)` 分支，
  开关读失败按「关闭」处理（宁可少一个缺陷，也不要让业务随机 500）。
- 菜单：见 §3.1；读失败按「放行」处理（避免整站不可用）。

编码与生效状态见 [doc/06](06-缺陷目录与开关.md)。

## 6. 内部接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/internal/switches?scope=&scope_id=` | 读当前生效开关 |
| PUT | `/internal/switches` | 覆盖某作用域开关 |
| GET | `/internal/bugs` | 缺陷清单（平台开关面板据此渲染） |
| GET | `/internal/menus` | 可关闭菜单清单（`[{code,name,name_en}]`），平台据此渲染开关面板 |
| GET | `/internal/health` | 存活 |

鉴权 `X-Internal-Token`：常量时间比较；令牌为空时只允许 `127.0.0.1`。

## 7. 测试

```bash
export TEST_MYSQL_DSN='root:***@tcp(127.0.0.1:23306)/'
go test ./... -count=1
```

- 每个用例建独立随机库、结束 DROP；未设 DSN 时自动 skip。
- 接口层用 `httptest` + 真实路由，覆盖状态码、权限、CSRF；
  `erp_api_test.go` / `erp_return_api_test.go` 覆盖单据与库存；
  `menu_gate_test.go` / `scope_test.go` 覆盖开关判定的安全边界。
- 目录约定：`internal/httpserver/*_test.go` 是集成测试，`internal/*/xxx_test.go` 是单元测试。

## 8. 已知边界

- 单实例部署：限流与定时任务不做多实例协调。
- 数据范围：所有登录用户看全部数据，由权限码控制「能不能改」，不控制「能看哪些行」。
- 仍有历史外键（`0014` / `0022` / `0024` / `0025`），删数据前要想清楚外键会不会拦住。
- 采购/销售只支持草稿编辑，审批后不可改（有意为之，见 [doc/08](08-与参考实现对照.md)）。
