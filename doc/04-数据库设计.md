# 04 数据库设计

> 库名固定 `pt_erp`；MySQL 8.0.16+，InnoDB，utf8mb4，`utf8mb4_0900_ai_ci`。
> 迁移在 `erp-system/server/internal/repository/migrations/`（29 个），服务启动时自动执行。

## 1. 约定

| 项 | 约定 |
| --- | --- |
| 主键 | `BIGINT UNSIGNED AUTO_INCREMENT` |
| 时间 | `DATETIME(3)`，连接固定 UTC（`loc=UTC`、会话 `time_zone='+00:00'`） |
| 布尔 | `TINYINT(1)` |
| 金额 / 数量 | `DECIMAL(18,2)` / `DECIMAL(18,3)`，不用 float |
| 枚举 | `VARCHAR(16)` + `CHECK`（8.0.16 起真正生效） |
| 保留字 | 避开或用反引号（`trigger` 已改名 `trigger_type`） |

**历史包袱**：`0014` / `0022` / `0024` / `0025` 里仍有真实外键（`FOREIGN KEY`）。
新表**不要再加**外键——关联只建普通索引，删除与级联清理由 service 事务负责。
在已有外键的表上删数据要留意外键会不会拦住。

## 2. 表清单

### 2.1 基础档案

| 表 | 关键字段 |
| --- | --- |
| `erp_customers` | code, name, contact, phone, address, payment_method, status |
| `erp_suppliers` | code, name, contact, phone, address, payment_method, status |
| `erp_categories` | parent_id, name, sort |
| `erp_brands` | name |
| `erp_units` | name, status |
| `erp_goods` | code, name, spec, category_id, brand_id, unit, unit_id, price, cost, purchase_price, sale_price, min_qty, status |
| `erp_warehouses` | code, name, location, keeper, phone, address |

分类 / 品牌 / 单位被商品引用后不可删除（服务端先计数再拒绝，409），避免商品失去归属。

### 2.2 库存

```sql
CREATE TABLE erp_stocks (
  warehouse_id BIGINT UNSIGNED NOT NULL,
  goods_id     BIGINT UNSIGNED NOT NULL,
  qty          DECIMAL(18,3) NOT NULL DEFAULT 0,
  updated_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (warehouse_id, goods_id),
  CONSTRAINT fk_stocks_wh FOREIGN KEY (warehouse_id) REFERENCES erp_warehouses (id),
  CONSTRAINT fk_stocks_goods FOREIGN KEY (goods_id) REFERENCES erp_goods (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE erp_stock_logs (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  created_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  warehouse_id BIGINT UNSIGNED NOT NULL,
  goods_id     BIGINT UNSIGNED NOT NULL,
  change_qty   DECIMAL(18,3) NOT NULL,
  biz_type     VARCHAR(16) NOT NULL,   -- purchase_in / sales_out / purchase_return /
                                        -- sales_return / adjust / transfer-in / transfer-out
  ref_no       VARCHAR(64) NOT NULL DEFAULT '',
  PRIMARY KEY (id),
  KEY idx_stock_logs_goods (goods_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

### 2.4 开关

| 表 | 关键字段 |
| --- | --- |
| `erp_switch_configs` | scope, scope_id, config_json, updated_at |

`config_json` 形如 `{"bugs":{"BUG-002":true},"menus":{"sales":false}}`，值都是布尔。
按 `scope + scope_id` 取配置；当前固定按 `all` 解析（见 [doc/06](06-缺陷目录与开关.md)）。

### 2.5 系统表

继承自 mini-ruoyi 骨架：`sys_users` / `sys_roles` / `sys_menus` / `sys_user_roles` /
`sys_role_menus` / `sys_role_perms` / `sys_sessions` / `sys_login_logs` /
`sys_oper_logs` / `sys_files` / `sys_jobs` / `sys_job_logs` / `schema_migrations`。

`sys_menus.buttons_json` 存页面按钮权限（`[{code,label_key}]`），`code` 与接口权限码完全一致。

## 3. 迁移策略

- 文件 `NNNN_描述.sql`，只向前、不回滚；改错用新迁移修。
- 启动时 `GET_LOCK` 串行 + 逐条执行 + `dirty` 标记；失败不要手工改 dirty 位，先修结构。
- 迁移后用 `information_schema` 校验建表名单。
- **新增迁移必须把 `internal/repository/migrate_test.go` 的 `migrationCount` 加一**；
  当前 29。
- 表结构变更同步更新本文件。

## 4. 每个实例一个库

平台开环境时可以给每个学生建一个独立空库（`pt_env_<env_uid>`），并把镜像启动命令里的
`APP_DB_NAME` 改写成它。**表由本系统自己的迁移创建**——平台只建空库，不碰表结构。
细节见 [doc/07](07-镜像与部署.md)。
