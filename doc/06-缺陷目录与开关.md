# 06 缺陷目录与开关

> 教学用：同一套 ERP，按需注入缺陷、关闭菜单，让学生在不同场景下做测试。
> 代码：`internal/service/switch_service.go`、`internal/handler/erp_handler.go`。

## 1. 缺陷码

| code | 现象 | 考察点 | 状态 |
| --- | --- | --- | --- |
| `BUG-001` | 采购/销售单金额 = 数量 × 单价 **少算 1 分** | 金额精度、边界值 | ✅ 生效 |
| `BUG-002` | 出库/调拨后库存**允许为负** | 库存约束 | ✅ 生效 |
| `BUG-003` | 允许**自己审批自己的**单据 | 越权 | ✅ 生效 |
| `BUG-005` | **已完成**的单据仍可编辑 | 状态机 | ✅ 生效 |
| `BUG-004` | 列表第 2 页重复第 1 页数据 | 分页/排序 | ⛔ 仅常量，未接线 |
| `BUG-006` | 删除客户后其订单仍可见 | 引用完整性 | ⛔ 仅常量，未接线 |

**写验收用例前先看这张表**：`BUG-004` / `BUG-006` 没有分支，打开也不会有任何变化。

代码位置：常量在 `internal/domain/erp.go`，分支用
`if s.switches.BugEnabled(ctx, domain.BugXXX, scope, scopeID)` 包住「正确实现」的反面。

## 2. 菜单开关

共 11 个 key，登记在 `internal/domain/erp.go` 的 `MenuSwitches`，与网关 `menuCodeOfPath`
一一对应（`TestMenuRegistryMatchesGateway` 守着两边不漂移）；平台通过
`GET /internal/menus` 读取它来渲染勾选项，所以平台代码里没有任何 ERP 的 key：

```
goods           商品（含分类/品牌/单位）
customers       客户
suppliers       供应商
warehouses      仓库
stock           库存（含调整/调拨/盘点）
reports         库存报表
purchase        采购
sales           销售
purchase_return 采购退货
sales_return    销售退货
audit           审核中心
```

- 未配置 = 可见；配成 `false` 后对应接口**直接 403**（`MenuSwitchGate`），不只是隐藏入口。
- 路径按资源段精确匹配：`/api/v1/sales-returns/3` 只命中 `sales_return`。
- 读取失败按「放行」处理，避免整站不可用。

## 3. 配置结构与作用域

```json
{"bugs":{"BUG-002":true},"menus":{"sales":false}}
```

- 存 `erp_switch_configs (scope, scope_id, config_json)`，值都是布尔；
  **别写 `"open"` / `"closed"`**——反序列化到 `map[string]bool` 会失败，整份配置失效。
- 缺失的键：缺陷按关闭、菜单按可见。
- 作用域 `all` / `group` / `personal`：本系统固定按 `all` 解析请求作用域，
  **不采信客户端自带的 `X-Switch-Scope`**（否则学生能自己把缺陷摘掉）。

## 4. 与实训平台的下发链路

```
老师勾选 → 平台 PUT /switch-configs
        → 平台库 biz_switch_configs（真源）
        → PUT {共享 ERP}/internal/switches        （只下发 all）
        → 开环境/重置/启动/保存时，把 all⊕group⊕personal 合并结果
          以 scope=all 推进该学生容器里的 ERP
```

- 每个学生独占一个容器，所以「个人/小组」在平台侧算好、物化成该实例的 `all`；
  容器里的 ERP 只需要认一层，不需要知道谁是小组。
- 容器内令牌按实例派生（`INTERNAL_TOKEN`，平台注入并改写启动命令）；
  部署级 `erp.internal_token` 只用于共享实例。
- 令牌出现在容器启动命令里，能进终端的学生读得到——他能关掉**自己**那份缺陷，
  但影响不到别人的容器（逐实例令牌的意义就在这）。

## 5. 教学建议

| 场景 | 配置 |
| --- | --- |
| 精度类缺陷 | 开 `BUG-001`，让学生核对金额、边界（0.01、大数量） |
| 库存约束 | 开 `BUG-002`，出库到负数，看余额与流水是否一致 |
| 越权 | 开 `BUG-003`，同一账号制单再自审 |
| 状态机 | 开 `BUG-005`，已完成单据再改一次 |
| 功能缺失类缺陷 | 关掉某个菜单，看接口是否 403、前端是否只是隐藏 |

排障入口：`GET /switches`（当前生效配置）、`GET /audit/switches`（库里所有作用域）。
